# CROSSREF 실물 검증의 현재 세션 자격

승인된 고정8종은 현재 Codex 실행 환경에서 시작할 수 없다. 한글 파일·등록 정보가 아니라 호출 프로세스의
상위 Job 종료 정책이 원 native startup 조건을 충족하지 못한다. 이 읽기 전용 판정은 한글을 실행한 결과나
P09 완료 증거가 아니며 기존 준비 구현·제품 시험은 그대로 보존한다.

## 외부 단일 진입점 준비 완료

Native 세션 자격·정상 종료·fresh 입력 대조를 마친 경우에만 원 고정8종을 순차 실행한다. 별도의 저장된
영수증이나 권한 flag로 세션 검사를 건너뛰지 않는다. 실제 세션과8종은 아직 NOT_RUN이다.

[411](evidence/p09-361-crossref-qualified-entry-code411.v1.json)은 신규36+영향6의 Python42 및

다음 사용자 실행 명령과 실패 시 조치는 [외부 실행 안내](P09_EXTERNAL_CROSSREF_HOST_RUNBOOK.md)를 따른다.

아래 절들은 이 진입점을 준비한 단계별 이력이며, 현재 연결 상태는 [전체 진입점 현황](P09_CROSSREF_QUALIFIED_ENTRY_PROGRESS.md)을 따른다.

## 실제 실행 전에 남은 연결

1. Codex의 미자격 상위 Job과 분리된 검증 호스트를 준비하고 실제 process/Job provenance를 확인한다.
   단순한 별도 터미널 실행이나 사용자 확인만으로 자격이 생기지는 않는다. 기존 jobless caller 조건을
   낮추지 않으며 실제 실행 전에 독립적으로 판정해야 한다.
2. 한글이 처음 실행되기 전의 자원 제한과 정확한 process/kernel birth/window/COM owner 결속을 검증한다.
   현재 sdk-baseline-owned-session의 New-P58Owner는 COM 생성 후 identity를 확인하고 case ports가 그 뒤
   admit_owned_process를 호출한다. 이 기존 사후 관측을 preassigned startup 자격으로 올릴 수 없다.
   새 연결은 원 소스/실패를 보존한 명시적 successor와 별도 자격이 필요하다.
3. 한 묶음의 고정8종을 각 독립 저장/재열기 세션에 연결하고 source/실행/산출물/정상 종료를 결속한다.
   접근 허용은 사용자만 처리한다. 시간 초과나 관측 실패를 재시작·강제 종료·재시도 허가로 사용하지 않는다.
4. 실제 매개변수·target ID/명령·필드/cache·원본 보존과 의미 차이·reopen 결과를 독립 readback으로 검증한다.
   callback 반환·JSON/해시·사전 준비 통과는 Native/상호참조 의미/Gate 통과가 아니다.

직접 실행 가능 답변에 따라 외부 사전검사001을 완료하고 독립 대조했다. 완료된 호출의 영수증을
향후 실제 세션의 live 자격으로 재사용하지 않는다. 이 답변으로 작업 스케줄러·상위 Job/보안 설정을 변경하거나
Native011·문자 스타일6종을 실행하지 않는다. 원 고정8종도 전체 세션 자격 후의 조건부 범위다.
