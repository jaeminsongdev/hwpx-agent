### 승인된 분리 정책 구현

`tools/p09/batch_verification.py`는 전체 보존 범위와 사례별 현재 범위를 함께 유지한다. 묶음 시작·종료에는 서로 다른 fresh reader로 전체 파일의 바이트와 해시를 확인한다. 이 두 관측이 묶음의 전후 경계이며 각 한 번의 관측을 기존 독립 자격 검사기의 두 번 읽기 완료로 표시하지 않는다. 사례마다 현재 범위에 대한 원래의 실제 Frame·잠금·전후 두 번 전체 읽기·Job 종료·동일성·cleanup 조건을 요구한다. 묶음 종료 감사가 끝나기 전에는 수용이나 원장 진전을 허용하지 않는다. 묶음 수명은 같은 프로세스·스레드에 한정되고 최대 8개 사례까지만 허용한다.

`install_scope`는 고정 SHA의 원 `current_input_scope` 함수 본문에서 직전 bootstrap 전부 재읽기를 묶음 보존 확인으로 바꾸고, 전체 선언에서 현재 입력을 선택하는 단계를 삽입한다. 그 밖의 원 AST를 정확히 역복원해 일치하는지 확인하고 원 함수·모듈은 수정하지 않는다. 기존에 다른 함수 변경이 있으면 이를 덮어쓰지 않고 거부한다. metadata reader는 보존 전용·미선언 입력을 원 IO 전에 거부하며, 압축 증거의 논리 pin과 실제 carrier pin도 구분한다. 예전 선언 주입이 현재 범위에 이력을 다시 넣는 경우에도 중단한다.

현재 보존 후보는 이전 사례의 runtime·acceptance·per-case data 기록만 보수적으로 고른다. 제품 소스·실행 파일·fixtures·검증 코드를 경로만 보고 제외하지 않는다. 실제로 선언된 준비 의존성과 직전 원장·candidate·worker 입력 232개를 우선 보호한다. 이 수는 전체 동적 의존성이 완전히 검증됐다는 뜻이 아니다.

### 실제 실행 연결 전 남은 경계

위의 3,309개 계획은 아직 `NEW` 상태이며 전체 시작·종료 감사, 실제 parent/worker 연결, 현재 동적 의존성의 완전성, 현재 비용과 metadata/Frame 공유 decoder 한도는 검증되지 않았다. 작은 4개 파일 IO와 mock handle을 사용한 Frame 계약 시험을 전체 제품 경로의 통과로 사용하지 않는다. 실제 속도 향상도 아직 측정하지 않았다.

다음 작업은 새 batch 객체와 private 입력 합성 어댑터를 실제 준비·parent·worker·독립 판정 경로에 연결하는 것이다. 기존 `inherit_declaration`이 현재 범위에 전체 이력을 다시 주입하지 않도록 명시적으로 연결하고, 묶음 종료 감사와 실제 제품 oracle이 모두 끝난 결과만 원장에 반영해야 한다. 여러 사례를 묶을 때의 임시 결과와 다음 사례 선택도 수용 결과를 미리 만든 것처럼 처리하지 않는다. 이 연결과 전체 검증을 끝내기 전에는 제품 실행으로 넘어가지 않는다. Native008/009 재실행 금지는 계속 유지한다.
