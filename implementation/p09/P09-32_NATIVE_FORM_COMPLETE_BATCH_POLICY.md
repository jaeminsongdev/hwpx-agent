# P09-32 complete native form batch policy

The P09-31 public package source capsule remains immutable. P09-32 adds disposable
six-case fixtures and independent preparation/native observers, not a source-lock
refresh or a product Gate. All predecessor raw sources, failures and native
captures are preserved. There is no stage, commit, push, original overwrite or
security/trust configuration change.

## Complete fixture admission

The generator uses actual public package APIs, actual original native capture,
complete maps and caller-declared policies. Defaults and validation behavior are
not inferred from native XML. Four original-capture cases cover enabled, colors
and editable, literal name/group, and existing catalog character properties.
Two derived complete packages cover two-section global tab order and a required
cross-section radio group. Derived inputs are not prior native save evidence.

Every case performs complete source binding, deterministic retry, stale-source
rejection, actual external output verification and actual complete target readback.
The independent Python preflight derives the exact source from the immutable
capture, derives requested attribute-value edits independently, compares every
expanded part and unchanged byte gap, and verifies entry order/compression and
complete maps. Raw ZIP headers are explicitly rewritten, not preserved. Python
does not claim a separately qualified full Rust domain-state serializer.

## One whole access-permission batch

All six distinct dependency-ready cases must pass preflight before dispatch.
Run the unchanged pinned x86/STA harness sequentially in one batch with six NEW
private attempt directories, two independent sessions per successful case.
Input/executable/security-module identity and read-only module registration
preflight must match. Hwp.exe must be absent before dispatch and between cases.
Human users alone handle security/access-permission dialogs. There is no automated
permission click, keystroke, trusted-module replacement or registry write.
Actual dialogs can appear sequentially; one batch is not one physical dialog.
Never repeat unchanged or invalid fixtures solely to increase the batch size.

Permission wait is not native failure. Keep observing the same live process and
attempt. Do not relaunch it after a command-observation timeout. If a case fails,
preserve its actual trace and stop on any residual/ambiguous Hwp process rather
than killing a user application or starting overlapping sessions.

## Evidence separation

The six-key lifecycle verifier binds actual input hashes and byte lengths to the
existing trace schema, exact target and two distinct owned session identities.
Whole-batch session identities must be independent. Permission-click attestation
remains `not_attested` unless separately evidenced; a successful lifecycle is not
permission-click evidence or semantics/render acceptance.

The independent native observer compares complete form subtrees, physical
anchors and referenced character definitions without erasing IDs, attributes,
geometry, text or unknown/opaque children. Complete expanded-part preservation,
entry ordering and compression are reported separately. Native raw drift and
semantic mismatches remain failures. No normalization is qualified by this
policy, and no refreshed fingerprint can convert a mismatch to PASS.

Actual public Rust package readback is separately required; a Python subtree
match cannot replace the complete product reader, policy binding or full global
state checks. Native output artifacts and trace hashes must be bound before
acceptance. PDF export remains an artifact, not rendered visual acceptance.

No production routing, general form insertion/input/default/validation behavior,
nonzero border, protection, rendering or product differential is qualified by
these cases. The authoritative P09 conformance inventory remains zero green;
P09 Gate and P10 admission remain open.
