# P09-58 현재 SDK 기준 수집 + 전체34 대기열

최신 사람 지시는 접근 허용을 띄우지 않는 것이다. SOURCE/검사/current는 한글/COM을
생성하지 않는다. `--execute-native`는 현재 금지이며, 나중에 사람이 실제 접근 허용
실행을 명시적으로 허용한 뒤 전체34만 실행하는 별도 경계다. subset/자동 재시도,
사용자 창 조작, 보안/registry 변경, 강제 종료, 원본 덮어쓰기는 하지 않는다.

## 실제 비교 기준의 의미

현재 P51 SDK target15개와 P22 보존 SDK target2개를 독립적으로 한글에 열고,
관리 속성/text/style setter를 적용하지 않고 별도 HWPX/PDF로 저장한다. 한 번 완전히
종료 후 새 owned session에서 새로 저장한 HWPX를 열어 다시 HWPX/PDF로 저장한다.
이것은 **SDK native baseline 수집**이지 사람이 직접 편집한 independent direct oracle,
semantic oracle, arbitrary document import 또는 제품 수락이 아니다.

P51의15개 SDK target은 자동화 입력과 같고, CLICK_HERE2개의 SDK target은
자동화 원본 empty/filled와 다르다. 두 경로의 원본과 기대 target SHA를 별도로 묶는다.
과거 direct PDF를 current 기준으로 복사하지 않는다. 실제17 current 기준 PDF는 없다.

## 소유권 / 저장 / 실패

- 실행 전 고정 complete17 bundle/source/harness/library SHA와 실제 x86 STA,
  installed EXE11.0.0.9136/automation DLL/security module 및 existing Registry32
  read-only 상태를 검사한다. 정확한 PreflightOnly prefix는 Add-Type/COM/새 native
  디렉터리 이전에 종료한다. library top-level은 함수 정의와 StrictMode뿐이다.
- HWND→PID와 birth/executable/session을 결합한다. Open 및 각 SaveAs 이전에도
  ownership을 다시 검사한다. 반환 document FullName으로 정확한 파일을 검증한다.
  collection index는 guarded candidate이며 native correctness가 아직 검증되지 않았다.
- dispose/Close(false)/Quit은 소유권 확인된 서버만 대상이다. quit 후 PID 실제 소멸을
  관찰하며 no-dirty-prompt 요청은 native 증거가 아니다. 원본 SHA는 실패/cleanup 뒤에도
  검사한다. 미확인 소유권/원본 변형/남은Hwp면 batch를 중단하고 모든 부분 증거를 보존한다.
- 자체 고정 attempt 폴더와 CreateNew trace만 쓴다. output 파일 존재 시 덮어쓰지 않는다.
  hash/bytes/PDF header/전체 expanded SDK package를 비교한다. raw XML/metadata를
  masking/정규화하지 않으며 malformed, partial/0bytes 및 package drift를 진단으로 남긴다.
- 실제 child exit, 엄격한 trace schema/typed claims/UTC/distinct owners/도달 가능한
  artifact prefix/cleanup/source identity와 actual disk bytes를 결합한다. 합성 trace는
  unit memory 안에만 있으며 private native/current/dispatch 증거로 쓰지 않는다.

## 전체34 실행과 소비

나중에 실행할 하나의 큐: SDK 기준17 → 기존 P56 **원래 전체15+2 dispatcher**.
첫 activation 전에 실제34 preflight를 요구한다. 각 activation 전후 새source와 전체
선행 context를 재검사하고, unresolved owner/source changes면 다음 activation을 막는다.
Native child는 접근 허용 대기 중 임의 timeout/kill/restart하지 않는다. 단위검사는
full dispatcher 연결을 확인하며 실제 native queue를 실행하지 않는다.

실제 whole34 receipt가 없으면 current0/NOT_RUN이다. 부분 기준이나 P56 단독 결과를
현재 direct baseline으로 승격하지 않는다. 완료된 실제 receipt가 있으면 전체17 pair
각각의 SDK baseline stability, automation stability, saved/reopened SDK-vs-auto를
P57 unmasked full-page96/192 renderer로 진단하고 입력을 다시 결합한다. 실패/거부/불일치
사례를 전체 목록에 남긴다. renderer 결과만으로 native 의미/제품/46개 reference Gate를
닫지 않는다. Current 조회는 native/current receipt를 쓰지 않는다.
