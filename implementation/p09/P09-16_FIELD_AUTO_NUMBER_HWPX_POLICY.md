# P09-16 Field auto-number HWPX policy

Status: `three_rows_closed_digit_static_section_integration_pass / target_not_run / non_green`.

## Exact admitted profile

`hwpx-agent.field-auto-number-hwpx.hwpml-2011-digit/v1` admits only the HWPML 2011
`ctrl/autoNum/autoNumFormat` shape for PAGE, PICTURE, TABLE and EQUATION counters. The format is
exactly `DIGIT`, `userChar/prefixChar/suffixChar` are empty, `supscript=0`, and `num` is a canonical
non-negative signed 32-bit decimal. TOTAL_PAGE, section numbering, alternate number formats,
decorators, superscript, missing/extra attributes, comments, stray text and local namespace payloads
fail closed.

The profile implements REF-006 page-number insertion, REF-008 picture/table/equation-number
insertion and the exact numeric-result subset of REF-009 field update. It does not claim the full
REF-009 installed-application recalculation path. The existing field-core pair identity remains a
domain reservation only: native `autoNum` carries no begin/end identity, so this adapter binds its
ordered projection and anchor instead of inventing an ID mapping.

## State, preservation and safety

Planning and lowering bind the complete field state, source and target document-flow digests,
complete source section, logical paragraph map, ordered native auto-number projection, domain plan
and sealed bounded adapter plan. Insertion adds exactly one namespace-compatible wrapper at one
normalized inline boundary. Update replaces only the selected canonical `num` attribute value.
Typed target projection is read back and every byte outside the declared edit is verified unchanged.

Input, XML elements, paragraphs, runs, auto numbers, paragraph IDs, plan JSON and output are finitely
bounded. Source/state/flow/map/projection/plan drift, unsupported field state, ambiguous transition,
malformed XML, invalid limits and allocation failure return no partial output. Debug output redacts
state, section, identity and digest values.
