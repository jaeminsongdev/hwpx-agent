# P09-90 댓글 컴포넌트 현재 소스 검증 정책

## 적용 범위와 실행 경로

원래 `tools/p09/validate_comment_model_contract.py`의 명시적
`--current-source-v2` 모드에서 동일한 comment-model/v1의 REF-026..REF-030
5개 컴포넌트를 현재 소스로 재검증한다. 댓글 삭제는 P11 범위다.
새 제품 스택, 댓글 API, 사용자 설정 또는 기본 실행 모드를 만들지 않는다.

기본 실행은 과거 v1 소스 잠금을 사용하고 `implementation_digest` 실패를 유지한다.
현재 모드는 모든 원래 계약·기능 소유권·상태 바인딩·실패 정책·문서·공식 구조
검사를 그대로 수행한다. 현재 구현 잠금은 별도로 고정된 v2 증거에서만 선택한다.
소스 지문을 호출자가 제출하거나 검사 결과의 오류를 제거해 통과시키지 않는다.

## 증거와 변조 거부

`evidence/p09-90-comment-current-source.qualification.v2.json`의 전체 바이트와
SHA-256을 먼저 확인한다. 현재 구현 3개, 권위 문서 4개, 원래 공식 소스 17개,
원래 계약·검증 기록·문서 5개, 실제 재실행한 Rust 검사 실행 파일 2개,
새 마이그레이션 문서 1개를 합친 32개 전체 파일의 바이트·크기·지문을 확인한다.
공식 소스는 고정된 로컬 checkout `1453388472c703a4b299a0834f425cdac16644b9`의
실제 파일이다. BOM을 보존한 UTF-8과 CRLF/CR→LF 정규화를 별도로 확인하며,
원래 상대 경로에 정확한 캐시 접두사만 붙여 전체 경로 기록과 대조한다.
줄바꿈만 변한 파일도 raw 잠금이 다르면 거부한다.

누락·변조·중복 JSON·잘못된 경로·알 수 없는 모드·실행 파일 불일치·원래 실패 정책
변경·native 또는 Gate 상태 승격을 거부한다. 임시 복사본을 사용하는 변조 검사는
테스트 소유 자료에만 적용한다. 실제 저장소를 대체해 PASS를 만드는 방식이 아니다.
이 검사는 파일 시스템의 원자적 보안 경계나 실행 권한을 증명하는 도구가 아니다.

## 보존과 한계

원래 댓글 Rust 모델과 검사는 변경하지 않는다. 원래 v1 계약·source qualification·
마이그레이션·정책·보고서·Python 검사는 수정하지 않는다. 공유 `lib.rs`의 현재 지문만
과거 v1과 다르고, 현재 소스에 대해 원래 Rust 검사 11개를 실제 재실행한다.
v1 결과와 현재 기본 결과의 모든 항목이 같은지 별도로 비교한다.

이번 작업은 댓글 컴포넌트의 현재 소스 검증이지 실제 HWPX 쓰기·native 작성자/시각/
표시/해결 상태 매핑·설치된 한글의 저장/재열기/렌더링·전체 댓글 제품 경로 완료가 아니다.
P09 Gate와 A12/A13은 OPEN, P26은 failed_semantic_non_green, P62는 UNRESOLVED,
native admission은 INPUT_CHANGED_RE_ADMISSION_REQUIRED, full native34는 NOT_RUN이다.
P10 새 구현은 시작하지 않는다. P09~P20 목표는 active로 유지한다.

사용자가 삭제한 루트 PLANS.md는 재생성하지 않는다. 접근 허용 창·Hwp·COM·UI는
실행하지 않는다. 기존 실제 검증·실패 증거와 원본 전체를 보존하며 이번 검증으로
그 상태를 올리지 않는다. 기존 conformance 검사는 계속 실패로 기록한다.
