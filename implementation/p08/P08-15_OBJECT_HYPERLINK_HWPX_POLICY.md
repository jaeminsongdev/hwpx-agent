## Exact native profile

The profile `hwpx-agent.object-hyperlink-hwpx.hwpml-2011-shape-component-root-href/v1` admits one existing direct
run-level `pic`, `rect`, `ellipse`, `line`, `arc`, `polygon`, `curve`, `connectLine`, `container`,
`ole`, or `video`, selected by bounded document order. A `rect` with exactly one direct
`drawText` child is a text box; zero is a basic shape and more than one fails closed. The admitted
typed kinds are picture, basic shape, text box, drawing canvas and embedded object.

The pinned public HWPML 2011 `AbstractShapeComponentType` model reads and writes one common root
`href` string. The v1 lexical profile maps no link to the empty string, an HTTPS link to its exact
validated URI, mail to `mailto:` plus the validated address, and an intra-document target to `#`
plus the validated bookmark token. HTTP, file, executable and script-style targets are not
admitted. The profile is static source-qualified; installed Hangul interpretation remains
unverified until the combined target campaign. The pinned `ChartType` instead directly inherits
`AbstractShapeObjectType` and has no common root `href`; chart therefore fails closed in this profile.

## Planning, preservation, and limits

Request planning and lowering independently bind and recheck the complete source and target
`ObjectPropertiesState` plus before/after document-flow SHA-256. The HWPX plan additionally seals
the exact section, selected object, source href, domain plan and plan SHA-256. A real transition
changes exactly one root `href` value span, proves every byte outside that span exact, and requires
typed target readback. Domain no-op requests are rejected before HWPX planning.

XML entities are decoded for semantic comparison and emitted canonically for the target attribute.
Section, element, object, href, output and plan sizes remain under finite hard ceilings. Plans are
deterministic bounded JSON. Public Debug output exposes link kind only and redacts identities,
targets, state and all binding digests.
