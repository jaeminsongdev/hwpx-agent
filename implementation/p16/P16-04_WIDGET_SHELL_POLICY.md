# P16-04 widget shell policy

## Decision boundary

P16-04 implements a React shell and a standards-first MCP Apps bridge. It adds one dedicated
read-only render-tool descriptor and one immutable versioned resource. The eighteen P15 workflow
tools remain UI-independent and are not modified.

The card may prove local component rendering, lifecycle behavior, resource construction and
deterministic bundling. It cannot prove ChatGPT Developer mode, an actual registered app, remote MCP
hosting, real tool authorization, Hangul/COM execution, file transfer or production submission.

## Resource contract

- URI: `ui://hwpx-agent/document-work/v1.html`
- MIME: `text/html;profile=mcp-app`, imported from `@modelcontextprotocol/ext-apps/server`.
- Presentation: inline, bordered when supported, smallest sufficient mode.
- CSP: empty `connectDomains` and `resourceDomains`; `frameDomains` is absent. The resource is one
  self-contained HTML document with inline CSS and JavaScript and no external network reference.
- Breaking HTML, JavaScript or CSS changes require `v2.html`; source-only compatible fixes may keep
  `v1.html` only while their generated bytes remain contract-locked.
- The self-contained HTML is capped at 700,000 bytes. This includes the audited MCP Apps SDK,
  React runtime, CSS and component code; it must not be reduced by moving code to an external CDN.

## Bridge contract

- Construct `App` with `strict: true`, `allowUnsafeEval: false` and automatic resize.
- Register tool-input, tool-result, cancellation and host-context notification listeners with the
  composable `addEventListener` API, plus the teardown request handler, before `connect()`.
- Missing tool input after initialization is `approval_pending`, not a connection failure.
- Theme and locale come from sanitized MCP Apps host context. Optional `window.openai` capabilities
  are detected by method presence only and are not required by this shell.
- The official helpers apply the validated document theme and host CSS variables. Host font CSS is
  not injected because this resource declares no external resource domain.
- Continue calls only `project_open` with an exact, bounded argument shape. UI data never authorizes
  the call; the server must authenticate and authorize it again.
- Teardown unregisters listeners and closes the bridge. A new explicit retry creates a fresh session.

## Data contract

Model-originated render input contains only its own schema version, client surface, locale and an
optional project ID. It is an approval signal and never moves the shell to `ready`. Only the
server-originated, output-schema-valid `structuredContent` can add revision and validation state and
move the shell to `ready`, and it is rejected unless approved input arrived first. Result
surface/project identity must match that approved input.
Component-only `_meta` contains only the local shell version and preferred inline mode. Unknown keys,
malformed identifiers, oversized values, paths, URLs, secrets and raw document content are rejected
without echoing the value.

## Dependency decision

- `@modelcontextprotocol/ext-apps@1.7.5` is required and must match the P16-01 integrity lock.
- `react@19.2.8` and `react-dom@19.2.8` provide the component runtime.
- `esbuild@0.28.2` produces the self-contained deterministic browser bundle. Its sole postinstall
  script selects a platform package and verifies its embedded version and SHA-256. Only `esbuild` is
  allowed to run a build script in `pnpm-workspace.yaml`; Inspector remains explicitly denied.
- `@openai/apps-sdk-ui` is not adopted: the small shell needs no component-library dependency and
  standards-first behavior remains easier to audit without it.
- The package-local TypeScript project uses bundler resolution and `skipLibCheck` only for external
  declarations because ext-apps 1.7.5 publishes extensionless internal declaration imports that do
  not type-resolve under NodeNext. HWPX Agent source remains strictly type-checked.
