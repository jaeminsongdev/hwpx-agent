# P16 PostgreSQL adapter: explicit source-binding successor

This is a source-binding evolution contract, not a phase completion, production permission,
registered-host receipt, durable Plan implementation or actual Hangul layout acceptance.

## Authority and immutable inputs

The reviewed adapter source is `217ba56cd8a88e4d3560a5735052b18880481ff4`. Its two actual disposable
PostgreSQL receipts bind the same 21 runtime/migration/harness source files. The original reports
remain at their original ignored run paths. The checked-in copies change CRLF to LF only; both
original and normalized SHA-256 values are recorded. They contain synthetic test identities and
hashes, not documents, SQL, credentials, host paths or raw backend diagnostics.

The existing P14 artifact contract remains byte-identical. The successor lists exactly three
replacements: the artifact-service manifest, service and store sources. Every entry binds both the
predecessor hash and the actual tested successor hash. Other P14 sources, SQL migrations, invariants,
fixtures and assertion counts retain the original validators. This contract cannot waive a root
Cargo lock or grant P15 qualification; those remain separate affected-contract work.

`tools/p16/postgres_artifact_qualification.py --check` requires both pinned receipts, their closed
schemas, successful ordered checks, successful cleanup, exact scope, matching source maps and
unchanged current runtime bytes. Missing explicit null fields, booleans replaced by numbers,
duplicate JSON keys, unknown fields, incomplete checks, source drift and changed proof bytes reject.
Paths and reads are bounded; links/junctions are rejected. Diagnostics contain fixed error codes.

The qualification also pins its own validator, tests, this policy and P14 integration code. Editing
those without qualifying a new contract fails. `--write` creates the new contract once and refuses
overwrite. This is a locally reviewed evidence chain, not independent hardware execution attestation
or protection against an adversary able to replace all trusted repository code and history.

## P14 integration and retained checks

P14 still checks its full unchanged migration/schema/constraint/rollback/smoke contract. A changed
source is admitted only if the complete successor validates AND the requested path and predecessor
hash match one of its three exact entries. Otherwise the original digest failure remains. The result
explicitly identifies successor-bound sources; it does not rewrite or silently reuse the old hashes.

SQL semantic validation precedes source-binding lookup so malformed migration mutations still reach
their dedicated checks. All source checks remain mandatory before successful return. Existing
negative tests keep their expected semantic failures; no skipped tests or relaxed assertions.
