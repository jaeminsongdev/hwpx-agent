# P08 object geometry v0 to v1 migration

There is no stored v0 object-geometry state, request, plan, native binding or lowering receipt. V1
adds the private `hwpx-agent.object-geometry/v1` schema and the deliberately bounded
`hwpx-agent.object-geometry-hwpx.hwpml-2011-common-component/v1` profile.

Earlier table placement, static picture insertion, arbitrary XML edits, synthetic screenshots and
manual Hangul saves are not v1 geometry plans or evidence. They MUST NOT be relabeled. A caller must
read one exact current run-level component, construct a fresh complete state-bound operation, then
bind its domain plan to the exact current section, object and document-flow digests.

V1 has no defaultable fields. Missing, duplicate, unknown, malformed or extra JSON fields fail.
Matrices require all 18 signed fixed-millionth coefficients; a rotation or flip request without the
complete target transform is not migratable. Nested group-member addressing, graphs/charts,
aspect-lock semantics, full-package publication and installed-target qualification require a new
profile/schema and explicit migration policy. Object protection is admitted only as the canonical
common root `lock` transition; it does not reinterpret `hp:sz@protect` as aspect locking.
